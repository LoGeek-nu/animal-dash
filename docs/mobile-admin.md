# スマホ管理画面

`/admin` は900px以下でスマホ専用UI、901px以上で既存PC用UIを表示する。共有セッション・WebSocket・レース計測・保存APIは変更せず、既存の `actions` を呼び出す。

## 操作

- **参加枠**：空きレーンの「選ぶ」から、そのレーン専用のキャラクター選択へ進む。配置済みレーンは解除ボタンで空ける。BOT補充とレース開始は独立した操作とし、スマホには「BOTで補充して開始」を表示しない。
- **キャラクター参照**：タブから直接開いた場合はセット不可で、セットボタンの左に鍵アイコンを表示する。カードのinfoボタン・長押し（550ms）で詳細を表示する。参照モードの通常タップでも詳細を開ける。
- **レーンへのセット**：未使用キャラクターのタップで選択し、下部の「レーンNにセット」で確定する。「選択解除」または参加枠タブへの移動で選択を解除する。配置先の切り替えUIや常設のステータス詳細は設けない。
- **同時操作**：別スタッフが配置先を埋めた場合や選択したキャラクターを使用した場合、セットを無効にする。これは既存の同期されたセッションから判定するUI上の防止策であり、通信基盤の同時更新方式は変更しない。
- **その他の操作**：アトラクト・参加待機・強制終了／結果スキップ・リセットをダイアログに集約する。操作の有効条件はPCと共通。強制終了とリセットには既存の確認を残す。ゲーム画面へのリンク・ログアウトもここに置く。
- **撮影**：既存のカメラ／画像選択・縮小・生成処理を利用する。最初にPCと同じ撮影開始ダイアログを表示し、「撮影 / 選択する」でカメラ／画像選択へ進む。画像の確認画面は全画面表示し、生成中、再試行可能／不可能なエラーも表示する。生成中の再送とダイアログ終了は無効にする。
- **詳細表示**：3つのステータスは紺色のバーと数値で表示する。レーン内はSPD・STMの2本のみ。ゲーム側のステータスやPC側の表示は変更しない。

参加枠の固定バーの実際の高さを `ResizeObserver` で測定してコンテンツ下部の余白に反映する。キャラクター画面は画面の高さに収め、一覧だけをスクロールする。ヘッダー・タブ・検索欄・操作欄はそのまま表示する。スクロールを始めたときは長押しを解除する。ダイアログはネイティブ `dialog` を使い、Escape、Tab／Shift+Tabの循環、閉じた後のフォーカス復帰、背面スクロールの抑止に対応する。

### 画像生成テストの再現

本番のGemini／image-pocは呼び出さず、ローカルの応答サーバーとローカルR2を使った。生成API本体からローカル上流へのmultipart送信、エラー応答、保存と一覧更新までを確認している。

1. `node tests/helpers/mobile-generation-fixture.mjs` を起動する。
2. ローカル専用の `.dev.vars` に以下を設定して `npm run dev -- --port 3001` を起動する。実際の本番シークレットは使わない。

```dotenv
STAFF_PASSCODE=mobile-ui-test
IMAGE_POC_API_URL=http://127.0.0.1:39002
IMAGE_POC_API_KEY=local-ui-fixture
```

3. `/admin` にログインし、撮影入口から `public/characters/keroppin/runner.png` を選択して生成する。
4. `.wrangler/ui-test/mode.txt` を `retry` にすると503を1回返した後で成功する。`success` は成功、`invalid` は再試行不可の422を返す。

実機の背面カメラ・OSの許可画面・iOS Safari・物理コントローラーは今回の環境では未検証。長押しは入力認識の自動テストで検証した。

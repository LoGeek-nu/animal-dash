# 観戦と操作権限

## 観戦する

来場者はログインせずに `/game` を開けます。待機・カウントダウン・レース・結果が、操作端末と同じレースセッションに追従します。初回の同期が届くまでは「現在のゲームに接続しています…」と表示します。

未ログインの画面には「観戦モードです」と、従来と同じ `/login?next=%2Fgame` へのリンクを表示します。スタッフが合言葉でログインして戻ると、操作端末の候補になります。合言葉を管理画面用とゲーム画面用に分ける必要はありません。

| 接続 | ログイン | 操作できること |
| --- | --- | --- |
| 観戦端末（`viewer`） | 不要 | 表示のみ。入力・進行変更・完了通知は送らない |
| 操作端末（`game`） | 必要 | 選ばれた1台だけがジャンプ・ダッシュ入力とレース完了を送る |
| 追加のゲーム端末（`game`） | 必要 | 選ばれるまでは観戦。操作端末の切断時に引き継ぐ候補になる |
| 管理端末（`admin`） | 必要 | レーン割り当て、開始、強制終了、リセットなどの管理操作 |

ゲーム画面の右上に、操作端末は緑の「✓ 操作可能」、その他の端末は「観戦中」と表示します。操作権の引き継ぎに合わせてチェックも移ります。通信が切れた端末は「通信切断」「操作不可」となり、再接続してサーバーから操作権が通知されるまでチェックは付きません。

最初に接続したスタッフのゲーム端末が操作端末になります。観戦端末を先に開いても操作端末には選ばれず、観戦端末しかいない状態ではレースを開始できません。操作端末の切断時は、接続済みの別のスタッフのゲーム端末へ操作権を移します。候補がいなければ、スタッフのゲーム端末が再接続するまで入力は再開しません。

管理画面とキャラクター生成・取り込みAPIには引き続きスタッフ認証が必要です。未ログインで `role=admin` / `role=game` のWebSocket接続を直接要求しても401となります。`viewer` 接続から入力や状態変更を直接送った場合は、ルームが `read_only` として拒否します。別サイトからのWebSocket接続も拒否します。

## レース中の同期

操作端末の入力は、サーバーが受信した時刻を付けて保存・配信します。観戦端末はその入力履歴と、出走時のキャラクターステータスを使い、確定結果と共通の固定ステップ処理で走行を再生します。位置、ジャンプ、ダッシュ、スタミナ、障害物との衝突が再現されます。通信にかかった時間ぶん、操作端末の表示と差が出ることはあります。

途中参加・再読み込み・再接続では、現在のセッション、レース開始時刻、出走情報、そこまでの入力履歴を受け取って現在位置まで追いつきます。受信時のサーバー時刻を端末の単調増加時計（`performance.now()`）に対応付けるため、観戦端末の時計がずれていても再生位置の基準にはなりません。

観戦端末ではキーボードのイベント登録とゲームパッドの読み取りを無効にします。ローカルでゴールしても完了通知を送らず、カウントダウン終了・結果表示終了のタイマーも状態変更を送信しません。通信断中は走行表示を止め、接続し直すとサーバーの状態から再生し直します。

レース結果はサーバーが計算した値で確定し、D1へ保存します。観戦端末から結果を確定・書き換えたり、他の端末を結果画面へ進めたりすることはできません。

## ローカルで確認する

1. `npm run db:migrate:local` でローカルDBを準備する。
2. `.dev.vars` に `STAFF_PASSCODE` を設定して `npm run dev` を起動する。未設定時の開発モードは認証を省略するため、未ログイン観戦の確認には合言葉が必要。
3. 通常のブラウザで `/game` のリンクからスタッフログインし、操作端末として開く。`/admin` でもログインする。
4. 別ブラウザやプライベートウィンドウで未ログインの `/game` を開く。レース開始、入力、途中参加、再読み込み後も同じレースを観戦できることを確認する。
5. 観戦画面でキーやゲームパッドを操作してもレースに影響せず、スタッフの操作端末の入力だけが反映されることを確認する。

この変更に追加のD1マイグレーションはありません。反映後は古い同期クライアントを残さないよう、管理・ゲーム・観戦の各画面を再読み込みしてください。

## 自動テスト

`npm run lint` と `npm test` を実行します。

- `tests/auth.test.mjs`：公開観戦接続とスタッフ用接続の認証、偽Cookie、別サイトからの接続拒否。
- `tests/race-session-room.test.mjs`：観戦端末の状態変更拒否、入力配信、操作権の引き継ぎ。
- `tests/spectator-race.test.mjs`：途中参加・再接続での位置と動作の一致、フレームレートによらない結果、古い通知の無視。
- `tests/race-session-channel.test.mjs`：観戦クライアントが状態変更・入力を送信しないこと。
- `tests/data-store.test.mjs`：実際のWorkersランタイムで認証、複数端末、途中参加・再接続、操作権の引き継ぎ、結果保存、生成・取り込みAPIへの未認証POSTの拒否を確認。
- `tests/rendered-html.test.mjs`：初回の接続待ち表示。

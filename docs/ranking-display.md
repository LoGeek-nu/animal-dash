# クリアタイムランキングの表示

Issue #46は、#45の確定結果を#44が保存・集計したデータを画面に表示します。取り込み順は **#45 → #44 → #46** です。

## 表示内容

- レース後の「THIS RACE」は今回の確定結果を表示します。未完走はDNFとし、意味を「未完走」と明記します。
- 「TODAY'S TOP 3」とアトラクト画面の3つ目「TOP 10」は、同じ日次ランキングAPIの先頭3件・10件を使います。
- 日本時間の対象日、クリアタイムの見出し、秒の単位を表示します。ミリ秒の差が分かるよう秒の小数点以下3桁を使います。
- APIの順位をそのまま表示し、同タイムの同順位を保ちます。名前と画像は記録に含まれるキャラクタースナップショットから表示します。
- 固定ランキングや未保存の今回の結果を日次ランキングへ合成しません。

集計の開催日、ベストタイム、BOT・DNFの扱いは[D1の共通仕様](./race-storage.md#今日のランキング)を参照してください。

## 保存完了と再取得

結果画面では`/api/rankings?date=YYYY-MM-DD&limit=10&afterRaceId=<raceId>`を取得します。APIは該当レースの保存有無を先に確認し、続いてランキングを取得して`afterRaceId`と`raceSaved`を返します。保存が未確認の間は「今回の記録を反映しています…」を表示し、過去のランキングを今回の反映済みデータとして見せません。

`results-saved`通知後に再取得します。通知を取り逃した場合も、保存待ちは1.5秒間隔で確認します。アトラクト画面は表示時に取得し、両画面とも30秒間隔・WebSocket再接続時にも更新します。日本時間で日付が変わった場合は新しい日付で取得します。古い通信は中断し、遅れて返ったレスポンスで新しいデータを上書きしません。

両画面は`app/features/rankings/`の取得状態を共有します。通信中、保存反映待ち、記録なし、取得失敗を別々に表示し、取得失敗と保存待ちには再読み込みボタンを用意しています。通信の上限は10秒です。DB障害・不正なレスポンス・取得失敗時に固定データへ戻す処理はありません。

開始前に強制終了したレースは保存対象ではないため、保存待ちをせず日次ランキングを取得します。

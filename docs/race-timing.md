# レースのクリアタイム計測

Issue #45の計測・確定結果の仕様です。保存と日次集計は後続のIssue #44、画面のランキングAPI接続は#46で扱います。

## レースの識別と開始

管理画面の「レース開始」または「BOTで補充して開始」で、アクション生成時に一意の`raceId`を発行します。カウントダウンから結果まで同じIDを使います。Reactの状態更新関数が再実行されても、同じアクションのIDは変わりません。

実際の開始基準は共有セッションの`countdownEndsAt`です。各端末の開始タイマーが遅れても、この値を`raceStartedAt`に使います。カウントダウンの時間はクリアタイムに含めません。

次のレースは同じレーン構成でも新しいIDを発行し、開始・完了日時、結果、走行状態を初期化します。旧形式の保存セッションには`sessionId:raceStartedAt`を使う互換処理があります。

## 計測と確定

`race-runtime.js`がレースごとの開始時刻、出走レーン、キャラクターステータス、走行状態、完了通知の状態を保持します。`useRaceEngine`は同じIDなら、同期によるレーンオブジェクトの置き換えやコールバック更新で計測をリセットしません。画面もレースIDをkeyにして、次のレースでは新しい状態で描画します。

初期化時の`Date.now() - raceStartedAt`に、その後の`performance.now()`の差分を加えて経過時間を求めます。ゴールを検出したフレームの経過時間を四捨五入し、整数ミリ秒の`finishedAt`として一度だけ記録します。着地やゴール後の移動では変更せず、確定結果には同じ値を`finishMs`として渡します。

レースの上限は60,000msです。各フレームは走行更新前に期限を確認し、期限に達した後で未完走のランナーを動かしてゴール扱いにしません。OSスリープ中に単調時計が進まない環境でも期限を守るため、絶対時刻でも期限を確認します。未完走は`finishMs: null`です。期限前に完走したランナーのタイムは維持します。

管理画面の強制終了は、個別の途中完走情報が管理端末に同期されていないため全員DNFにします。仮のクリアタイムは作りません。レース開始前の強制終了はD1の保存対象になりません。

## 完了通知と保存への受け渡し

完了通知はレースごとに一度だけ発行します。

```js
{
  raceId: "race_<unique-id>",
  completedAt: 1791601260000,
  results: [
    { characterId: "momo", lane: 1, rank: 1, finishMs: 30000, isBot: false },
    { characterId: "toramaru", lane: 2, rank: 2, finishMs: null, isBot: true }
  ]
}
```

セッションReducerは現在のレースIDと出走レーンを照合し、不正なタイム・レーン・BOTフラグ、旧レースからの遅れた通知を拒否します。カウントダウン開始・結果終了のタイマーにもIDを付け、旧レースのタイマーが新しいレースを開始・リセットしないようにします。

結果の配列をコピーし、開始日時と別に`raceCompletedAt`を固定します。同期更新日時の`lastSync`が変わっても、D1へ渡す完了日時と結果は変わりません。同タイムの今回のレース順位はレーン順で決めます。日次ランキングの同順位とは別の仕様です。

## 検証

`tests/race-timing.test.mjs`で複数のゴール時刻、ゴール後の固定、60秒の期限、連続レース、古い通知・タイマー、不正結果を確認します。D1への保存とランキング集計の結合テストは、後続の#44で追加します。

時計・フレームの仕様: [Performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)。

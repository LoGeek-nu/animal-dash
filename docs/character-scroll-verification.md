# キャラクター400枚のスクロール検証（Issue #88）

## 再現手順

本番や通常のローカルDBに触れず、`outputs/issue88-scroll/` 内だけにD1・R2の検証データを作ります。

```bash
npm run build
node scripts/seed-character-scroll-test.mjs
npx wrangler dev --local --config outputs/issue88-scroll/wrangler.json --persist-to outputs/issue88-scroll/state --port 8788
```

`http://localhost:8788/admin` を開き、検証専用の合言葉 `issue88-local-test` でログインします。スクリプトは、静的8種類のPNGを異なる400個のR2キーへ保存し、同じ登録日時のケースを含む400体をD1へ登録します。PNGの合計は203,892,800 bytesです。通常のR2画像APIを通じて配信し、サムネイルやダミーの小さな画像は使用しません。

1. PC表示で初回が12件であることを確認する。
2. 一覧内を末尾へスクロールし、12件ずつ増えることを確認する。
3. 生成400体と静的8体の計408件で「すべて表示しました」になることを確認する。
4. 一覧の画像が408枚、画像URLが408種類、`complete && naturalWidth > 0` が408枚であることを確認する。
5. 390×844pxへ変更して再読み込みする。参加枠タブでは生成画像が0枚であることを確認する。
6. キャラクタータブを開き、同じ初回12件から末尾408件までのスクロールを確認する。
7. 再読み込み後に「検証アニマル000」を検索し、初回未取得だった古いデータが1件表示され、スクロール位置が先頭へ戻ることを確認する。
8. 「スタミナ」でタイプ検索、存在しない名前で0件表示を確認する。

## 2026年11月1日の検証結果

ビルド済みWorkerをWranglerのローカルモードで起動し、ブラウザで確認しました。

| 項目 | PC | モバイル 390×844px |
| --- | --- | --- |
| 初回一覧 | 12件 | 12件 |
| スクロール後の最終件数 | 408件 | 408件 |
| 生成画像 | 400枚 | 400枚 |
| 読み込み完了の画像 | 408 / 408枚 | 408 / 408枚 |
| 壊れた画像 | 0枚 | 0枚 |
| 末尾表示 | すべて表示しました | すべて表示しました |

PCの画像URLは408種類で重複なし。モバイルの参加枠タブは画像2枚（静的BOTのみ）で、非表示のPC一覧から生成画像を取得しませんでした。未取得データの名前検索、タイプ検索、0件表示も成功しました。

スクリーンショットはGit管理外の `outputs/issue88-scroll/desktop-400.png` と `mobile-400.png` に保存しています。ローカル通信による機能検証であり、文化祭会場の回線速度や実機スマートフォンの描画性能の計測ではありません。全件を最後まで見ると画像の累計通信量は約204MBになるため、今回の変更で減らす対象は初回と未閲覧分の読み込みです。

DB・クライアントの自動テストでは、400件の継続取得、同時刻のID順序、途中追加時の重複・欠落防止、カーソル・件数の検証、検索変更時の応答競合、再試行、ページ外キャラの同期取得も確認します。

最終確認: `npm run lint` 成功、`npm test`（ビルドを含む）128件すべて成功。

# ANIMAL DASH! 追加修正用実装計画 v0.4

- 文書バージョン: 0.4
- 作成日: 2026-08-19
- 対象: JavaScript / JSX版 ANIMAL DASH! モック
- 基準バージョン: v0.3（commit `786f943`）
- 対象画面: `/admin`、`/game`

---

## 1. 改修の目的

v0.4では、次の5点を重点的に改善する。

1. 管理画面のドラッグ＆ドロップを「右側へ運んだときだけ反応する」自然な操作へ変更する
2. アトラクト画面の遊び方説明を、実際のゲーム内容が理解できる品質まで作り込む
3. レース画面の障害物、背景、演出を改善し、手描きゲームとしての完成度を上げる
4. アトラクト3画面の表示時間を、それぞれ約3秒短縮する
5. 待機画面の文言、カード比率、操作説明、不要な装飾を整理する

ゲームルール、最大4レーン、既存キャラクター10体、認証なしの公開構成は変更しない。

---

## 2. 現状確認と原因

### 2.1 管理画面のDnD

現在は次の構成になっている。

- ドラッグ判定に `closestCenter` を使用している
- キャラクターを持ち上げた時点で `activeCharacterId` が設定される
- `activeCharacterId` があるだけで画面全体を暗くし、右ペインと全レーンを発光させている
- `closestCenter` はポインターが左側にあっても、最も近いレーンをドロップ候補として返す

このため、左側でキャラクターを少し動かしただけでも、右側のレーンが選択状態に見える。実際にはレーン外へドロップするとキャンセルされるが、見た目として「どこかに必ずセットしなければならない」状態に感じられる。

### 2.2 アトラクト画面の遊び方

現在の遊び方画面は、1つのデモ映像領域、短い説明文、簡易ランナー、ログと岩のCSS図形で構成されている。公開版を確認すると次の問題がある。

- 操作説明が「ジャンプで障害物をとびこえる」に偏っている
- BOOST、スタミナ、ゴールまでの流れが十分に説明されない
- デモ領域の障害物が灰色・茶色の矩形に近く、ゲーム本編の雰囲気が伝わらない
- ランナーと障害物の位置関係が分かりにくい
- 動画が利用できない場合のフォールバック表示が簡素すぎる

### 2.3 レース画面

コースは5区間、障害物は6種類まで増えているが、障害物の多くを単純なCSS矩形・楕円で描画している。1920×1080の実画面では、複数の障害物が先まで同時に並び、各障害物の意味と当たり判定が直感的に分かりにくい。

### 2.4 待機画面

現在の見出しは「キミのキャラが走りだす！」で、参加者登録中であることが伝わりにくい。また、空きレーンの `?` の右下に `+` があり、押せるボタンのように見える。

キャラクター右上・左下の白い丸は、共通 `CharacterAvatar` に追加されている `.avatar-spark` 装飾である。そのため、待機画面だけでなく管理画面、レース、ランキングにも表示される。

## 3. 管理画面DnDの修正

### 3.1 目標となる操作

ドラッグ操作を次の状態遷移に変更する。

```text
キャラクターを押す
  ↓
8px以上動かす
  ↓
キャラクターが持ち上がる
  ├─ 左側にいる間: 通常表示のまま。レーンは光らない
  ├─ 右側へ入る: 右ペインが明るくなり、レーンがドロップ候補になる
  ├─ 特定レーン上: そのレーンだけをさらに強調する
  ├─ 右側から出る: 強調を解除する
  └─ レーン上で離す: そのときだけ登録する
```

左側、ペイン間の余白、ヘッダー、操作バー上で離した場合は、セッションを一切変更せずキャンセルする。

### 3.2 衝突判定の変更

`closestCenter` をポインター操作の主判定に使用しない。ポインターが実際にレーン内へ入った場合だけ候補を返す `pointerWithin` ベースの判定へ変更する。

- ポインター操作: `pointerWithin` の結果を `lane-*` に限定する
- ポインターがレーン外の場合: 空配列を返す
- キーボード操作: 移動後の矩形がレーンと交差した場合のみ `rectIntersection` を利用する
- レーン以外の要素を `over` として扱わない

`onDragEnd` では次をすべて満たす場合だけ `assignCharacter` を呼ぶ。

- 編集可能フェーズである
- `characterId` が有効である
- `over.id` が `lane-*` である
- `laneIndex` が0〜3の整数である

### 3.3 表示状態の分離

現在の `activeCharacterId` だけで全体を暗くする方式を廃止し、次の状態を分ける。

- `activeCharacterId`: 持ち上げているキャラクター
- `overLaneId`: 現在ポインターが重なっているレーン
- `isOverLaneZone`: 右側レーン領域内に入っているか
- `didDragRef`: ドラッグ終了直後の不要なクリックを抑止するフラグ

CSSクラスも分離する。

- `.is-dragging-character`: ドラッグオーバーレイと元カードの半透明化だけに使用
- `.is-over-lane-zone`: 右ペインの明るさ、輪郭、影を有効化
- `.is-drag-over`: 実際に重なっている1レーンだけを強調

ドラッグ開始直後に全画面へ暗いオーバーレイを出さない。右側へ入ったときだけ左側を少し減光し、右側を明るくする。

### 3.4 クリック操作

ドラッグできない環境向けのクリック操作は残す。ただし、クリックだけで自動登録は行わない。

1. キャラクターをクリックして明示的に選択
2. 右側の「このレーンにセット」をクリック
3. その時点で登録

ドラッグ後に同じカードの `onClick` が発火して選択状態になる現象は `didDragRef` で防止する。

### 3.5 DnD完了条件

- 左側で持ち上げただけでは右側も画面全体も発光しない
- 右側のレーン領域へ入った瞬間だけ右ペインが明るくなる
- ポインター下の1レーンが他レーンより強く表示される
- 右側から左側へ戻ると発光が解除される
- レーン外で離しても人数、レーン、`sequence` が変化しない
- 空きレーンへの追加、使用中レーンへの交代が正しく動く
- キーボードまたはクリックでも登録できる

## 4. アトラクト画面「遊び方」の再設計

### 4.1 基本方針

単純なデモ映像1枚ではなく、21秒の中で3つの操作を順番に説明するミニチュートリアルへ変更する。

| ステップ | 時間 | 内容 | 画面上の説明 |
|---|---:|---|---|
| 1. JUMP | 7秒 | 岩へ近づき、ボタン入力、ジャンプ、着地 | 「障害物の手前でジャンプ！」 |
| 2. BOOST | 7秒 | 通常走行と加速を比較し、スタミナを消費 | 「長押しで加速。ゲージに注意！」 |
| 3. GOAL | 7秒 | ジャンプと加速を組み合わせてゴール | 「うまく使って1位をめざそう！」 |

### 4.2 レイアウト

- 左または上部に `01 JUMP / 02 BOOST / 03 GOAL` のステップ表示
- 中央にゲーム本編と同じ比率のデモレーン
- 操作ボタンを押した瞬間に、ボタンが沈むアニメーションを付ける
- ジャンプ軌道を点線または矢印で一時表示する
- BOOST時はスピード線、土煙、スタミナゲージの減少を見せる
- 障害物通過後に「NICE!」の短い成功表示を出す
- 各7秒の進行を下部のプログレスで示す

### 4.3 ゲーム本編との共通化

デモ専用の灰色・茶色の矩形を廃止する。次を本編と共有する。

- `CourseObstacle`
- `RunnerSprite`
- `StaminaMeter`
- `CourseGround`
- ジャンプ、BOOST、衝突時の視覚効果

外部動画の読込成否で表示品質が変わらないよう、チュートリアルの主表示はReact/CSSアニメーションで構成する。既存MP4は補助素材として残す場合でも、表示の必須条件にはしない。

### 4.4 説明文

現在の「ジャンプで障害物をとびこえよう！」だけの説明を、次へ変更する。

```text
遊び方はかんたん！

JUMP
障害物の少し手前で押そう

BOOST
長押しでスピードアップ
使いすぎるとゲージがなくなるよ

GOAL
ジャンプと加速を使い分けて1位をめざそう！
```

### 4.5 アトラクト表示時間

各シーンを現在より3秒短縮する。

| シーン | v0.3 | v0.4 | 差分 |
|---|---:|---:|---:|
| ANIMAL PARADE | 12秒 | 9秒 | -3秒 |
| DEMO RACE | 24秒 | 21秒 | -3秒 |
| TODAY'S RANKING | 14秒 | 11秒 | -3秒 |
| 1周合計 | 50秒 | 41秒 | -9秒 |

`ATTRACT_SCENES` を `attract-data.js` へ分離し、画面表示、進行バー、テストが同じ値を参照する。

## 5. レース画面と障害物の改善

### 5.1 障害物の描画

障害物を単純なCSS図形から、太い手描き輪郭と細部を持つ専用部品へ変更する。物理判定値と見た目を分離し、見た目を改善してもゲームバランスが変わらない構成にする。

| 種類 | 見た目の改善 | 読み取りやすさ |
|---|---|---|
| 岩 | 不規則な輪郭、割れ目、苔、小石 | 高さを輪郭で明確化 |
| 干し草 | 藁の線、赤いひも、飛び出す穂 | 黄色と赤で背景から分離 |
| 丸太 | 年輪、樹皮、短い枝、落ち葉 | 接地面と上端を明確化 |
| 泥 | 複数のしぶき、足跡、濃淡 | 踏む障害物であることを表示 |
| 水たまり | 水面反射、波紋、水滴 | 泥との色・形の違いを強化 |
| ハードル | 支柱、横棒、チェック柄の旗 | 飛び越える高さを明確化 |

障害物の素材は `public/course/obstacles/` のローカルSVG、または同等品質のコード描画として管理する。すべて透明背景とし、外部通信へ依存しない。

### 5.2 当たり判定の可視整合

- 透明な `.obstacle-hitbox` と見た目の `.obstacle-artwork` を分ける
- `hitHeight` と見た目の上端が大きくずれないようにする
- 接地障害物の泥・水たまりは低い判定として表示する
- ジャンプ成功時にキャラクターの足が障害物へ不自然に食い込まない
- 衝突時は星、揺れ、短い減速表示を付ける

### 5.3 一度に見せる障害物の整理

現在はコース後半の障害物まで早い段階から表示されやすい。表示対象をランナー基準で整理する。

- 後方: 約2〜3進行単位まで
- 前方: 約30〜35進行単位まで
- 通常時に画面内へ出す主要障害物は2〜3個程度
- 警告は最も近い未通過障害物だけに表示
- 遠い障害物は表示しない

### 5.4 コース背景

5区間の違いを次の要素で強める。

- START YARD: スタートゲート、応援旗、校舎
- FLOWER GARDEN: 花壇、花びら、低い柵
- LOG BRIDGE: 水面、丸太橋、木立
- MUD FEST: 屋台、提灯、泥はね
- FINAL STRAIGHT: 観客、紙吹雪、チェッカーフラッグ

遠景、中景、前景の移動量を変え、スクロールしていることが分かるパララックスを維持する。4レーンすべてへ過剰な装飾を重ねず、背景の情報量はレースキャラクターと障害物より低くする。

### 5.5 ランナー演出

- キャラクターを現在より約10〜15%大きくする
- 接地影を追加し、ジャンプ高度を読みやすくする
- BOOST中だけ速度線と土煙を強める
- ジャンプ中は接地影を縮小する
- 衝突中は短時間だけ星と表情吹き出しを表示する
- ゴール時はキャラクターを隠さず `GOAL!` を表示する

ゲーム速度、スタミナ計算、順位計算はv0.3を維持し、視覚改善による意図しない難易度変更を避ける。

## 6. キャラクター待機画面の修正

### 6.1 見出し文言

「キミのキャラが走りだす！」を削除し、登録作業中であることが分かる文言へ変更する。

```text
NEXT RACE
キャラクター選択中…
4人集まったらエントリー完了！
```

人数表示は次のように切り替える。

- 0〜3人: `あとN人でエントリー完了`
- 4人: `エントリー完了！ スタートを待ってね`

### 6.2 カードをさらに縦長にする

見出し領域を小さくし、その分をカードへ割り当てる。

| 領域 | v0.3目安 | v0.4目安 |
|---|---:|---:|
| 見出し | 18vh | 11〜12vh |
| カード | 54vh / 420px以上 | 60〜62vh / 470px以上 |
| 操作説明 | 13vh | 12〜13vh |

カード内部は引き続き次の3段構成とする。

1. レーン番号
2. キャラクター全身イラスト
3. 名前、タイプ、SPD / ACC / JMP / STM

イラスト領域の上下余白を増やし、耳、尻尾、足が窮屈に見えないサイズへ調整する。

### 6.3 JUMP / BOOST説明の位置

- カード下端との間に十分な空白を取る
- フッター内で下寄せする
- 画面最下部からは安全余白を確保する
- カードの影とボタンが接触しないようにする
- 1024×768でもカード、操作説明、待機メッセージを同時に表示する

### 6.4 不要な「＋」の削除

空きレーンは `?` と「参加者を待っています」だけにする。

- `.empty-card-art i` のJSXを削除
- 対応CSSを削除
- 押せる要素と誤認する装飾を置かない

管理画面の明示的な登録ボタンは削除対象に含めない。

### 6.5 白い丸装飾の削除

共通キャラクター部品から次を削除する。

- `.avatar-spark.spark-one`
- `.avatar-spark.spark-two`
- `.avatar-spark`、`.spark-one`、`.spark-two` のCSS

キャラクター画像そのものの白いハイライトや透明背景は変更しない。削除対象はコードで重ねている2つの丸装飾だけとする。

## 7. コンポーネント構成

v0.4では、アトラクトとレースで同じ見た目を使えるよう次の構成へ整理する。

```text
app/
├─ AnimalDashApp.jsx
├─ attract-data.js
├─ course-data.js
└─ components/
   ├─ admin/
   │  ├─ DraggableCharacter.jsx
   │  ├─ LaneDropTarget.jsx
   │  └─ LaneDropZone.jsx
   ├─ character/
   │  └─ CharacterAvatar.jsx

   │  ├─ RunnerEffects.jsx
   │  └─ WaitingScreen.jsx
```

## 8. 実装順序

### Phase 0: 基準画面の記録

- 公開版 `/game` と `/admin` の現状を確認
- アトラクト遊び方、待機画面、レース5区間を基準画像として記録

### Phase 1: DnDの判定修正

- `pointerWithin` ベースの衝突判定を実装
- `overLaneId` と `isOverLaneZone` を追加
- ドラッグ開始時の全画面減光を削除
- 右側へ入ったときだけ明るくするCSSへ変更
- ドロップ外キャンセルとドラッグ後クリック抑止をテスト

### Phase 2: 不要装飾と待機画面文言

- キャラクターの白い丸を共通部品から削除

### Phase 3: 障害物共通部品

- `CourseObstacle` を作成
- 6種類の障害物素材を作成
- 見た目と当たり判定を分離

### Phase 4: レース画面の演出

- 区間背景を強化

### Phase 5: アトラクトチュートリアル

- 本編の障害物とランナー演出を再利用
- JUMP / BOOST / GOALの3ステップを実装
- 7秒ごとの内部進行を実装

### Phase 6: 総合検証と公開

- build、lint、自動テスト
- 実ブラウザでDnD、待機、アトラクト1周、レース全区間を確認
- コンソールエラーと画像404を確認
- 公開版へ反映し、`/game` と `/admin` を再確認
